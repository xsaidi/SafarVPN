# Android changes pending the user's next release

The user subsequently requested the build: these changes are now packaged in **1.4.22/code60**. See `RELEASE-1.4.22.md` for the APK and verification. The bot still distributes the previously published 1.4.21 APK. No phone installation was performed. This note records source/build verification before GitHub publication.

- Expired account subscriptions retain their saved server profiles, including across restarts. Retention filters by the authenticated owner; logout still removes account profiles and leaves manual ones alone. Selecting a saved server is allowed, but connecting with an expired subscription displays «Подписка истекла. Продлите подписку…» in the logs. Cached expiry dates are interpreted even if the server describes revoked expired credentials. An expired account on a fresh installation cannot recover credentials from the server: the existing API intentionally returns no credentials after expiry; this change preserves the locally saved list.
- The account-subscription refresh notice uses `onSurfaceVariant` and remains readable in dark mode.
- Device management is now an expanded Material 3 bottom sheet following the user's reference: header/icon, clearly separated actual occupied limit and editable target, price information card, device cards, pending/success notices, a green confirmed-success state and a large Close button. Actual server-confirmed counts are never replaced by the tentative selected target. Unbind and quoted paid-limit flows remain unchanged.
- Every foreground Activity entry checks `https://api.github.com/repos/xsaidi/SafarVPN/releases/latest`. Stable newer releases with the expected universal APK asset trigger a prompt. No downgrade/equal-version prompt. Download is user-initiated, bounded to the declared size, and restricted to the repository's GitHub release URL and GitHub asset hosts through every redirect. SHA-256 is checked when GitHub supplies it; installed package ID, higher version code, expected version name and the permanent installed signing certificate are always checked before offering Android installation. Android grants/installation remain user-controlled. API errors/rate limits do not block normal use. On 17 October the observed latest was 1.4.20, older than installed 1.4.21.
- A one-time settings migration adds the concrete domains from the user's list and a curated set of service package IDs to the existing Bypass tab. Existing rules precede defaults, including CIDR strings, and the current 100-rule cap remains. Deletions after seeding are respected. Explicit app-whitelist mode is preserved rather than reversing selected apps into a different policy. Whole `.ru`, `.рф`, `.su` zones are excluded by the user's follow-up choice. Websites use the existing IPv4 DNS-to-route mechanism, not an all-subdomains traffic classifier; applications use the existing Android per-package exclusions. Operator reachability is not guaranteed by the preset.
- The new server trial label is retained and shown as «Пробный период · 2 дня». The 48-hour grant itself is deployed separately; see `../auth-integration/mobile-trial-20261017/DEPLOYED.md`.

Tests cover version ordering, stable universal asset selection, untrusted redirects, preservation/idempotency of bypass defaults, account-owned profile retention, cached and server-revoked expiry, trial label, and the earlier device-admission fixes. The final Gradle command is `:app:testDebugUnitTest -x buildNativeLibs -x buildServerAsset --offline`; it compiles/tests code but does not package APK/native outputs. UI/device runtime QA is deferred until a release is authorized.

Final source verification passed: **55 Android unit tests**, zero failures/errors; no APK packaging tasks were invoked. The separately deployed backend passed **12 isolated tests**. Existing Android deprecation/manifest warnings remain unrelated to this change.
